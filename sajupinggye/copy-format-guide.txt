사주핑계 인스타그램 원고 교환 가이드 · v1

1. 가장 쉬운 사용 순서

① 콘텐츠 작업실에서 ‘GPT로 문구 일괄 교체’를 열고, ‘GPT 작업 ZIP 받기’로 현재 원고를 내려받아.
② ChatGPT Pro에 ZIP 파일을 통째로 첨부하고 copy-editing-prompt.txt 내용을 붙여 넣어. ‘ZIP의 all-posts.json 전체를 한국어·일본어·영어 모두 다듬어 달라’는 요청이야.
③ Pro가 돌려준 all-posts-edited.json 파일을 내려받아. 기본 키트라면 한국어 139개·일본어 139개·영어 139개, 총 417개가 들어 있어야 해.
④ 같은 작업실의 ‘GPT 수정본 가져오기’로 올려. 여러 JSON 파일을 한꺼번에 고를 수 있어.
⑤ 바뀌는 원고·언어·문구와 충돌 여부를 미리 보고 ‘검토한 문구 적용’을 눌러.
⑥ 카드 미리보기로 줄바꿈을 확인한 뒤 3장 ZIP으로 게시물을 만들어.

ZIP은 그대로 첨부하면 돼. GPT가 처음부터 세 언어 전체를 작업하도록 원고는 중복 없는 all-posts.json 하나로 묶었어. 다만 모델의 실행·출력 한도에 따라 한 번에 끝내지 못할 수 있어. 미완료 안내가 나오면 같은 대화에서 남은 작업을 이어 달라고 해. ko 파일만 받았거나 다른 언어를 검토하지 않은 채 원문으로 채워 넣었다면 전체 작업이 끝난 것이 아니야. ‘원본의 일본어와 영어도 실제로 검토·수정하고, 세 언어의 모든 행이 담긴 all-posts-edited.json을 만들어 줘’라고 요청해.

2. 이 기본 다운로드 키트에 담긴 것

- all-posts.json: 한국어 139개·일본어 139개·영어 139개를 합친 원고 417개. 유일한 원고 입력 파일이야.
- copy-editing-prompt.txt: Pro에 붙여 넣을 편집 지시문.
- copy-format-guide.txt: 이 파일.
- manifest.json: 파일별 개수와 구성 확인용. 가져오기 파일이 아니야.

기본 키트는 최신 100개 기획 × 3개 언어인 300개 원고, 이전 33개 기획 × 3개 언어인 99개 원고, 초기 6개 기획 × 3개 언어인 18개 원고를 합친 417개 원고야. 대부분 3장이며 초기 18개 원고는 기존 5장 형식을 유지해. 사진은 포함하지 않아.

ZIP에는 위 네 파일만 있어. 언어별 전체 파일과 배치 파일을 함께 담지 않아 같은 원고를 중복해서 작업할 일이 없어. 예전에 받은 ko-all.json / ja-all.json / en-all.json도 기존 규격으로 사용할 수 있지만, 그중 하나만 수정했다면 해당 언어만 작업한 상태야.

사이트에서 제공하는 기본 키트에는 네 브라우저에서 따로 편집한 글이나 새로 복제한 기획은 들어 있지 않아. 이미 작업한 내용이 있다면 작업실의 ‘GPT 작업 ZIP 받기’로 현재 원고를 받아. 이 ZIP의 manifest.json에는 현재 원고의 전체·언어별 개수가 적혀 있어. 글을 내보낸 뒤 가져오기 전까지 같은 원고를 직접 수정하면 충돌 안내가 나올 수 있어. 그때는 최신 원고를 다시 내보내서 작업해.

3. 교환 규격

파일 인코딩: UTF-8, 확장자: .json
최상위 필드: format, version, posts
format: sajupinggye-instagram-copy
version: 1
posts: 원고 객체의 배열. 한 행은 기획 하나의 언어 하나야.

행마다 다음 필드를 빠짐없이 넣어.

id            기획 ID. 수정 금지.
locale        ko / ja / en 중 원래 값. 수정 금지.
baseRevision  내보낼 당시 원고를 확인하는 16자리 값. 수정 금지.
topic         제작용 주제 이름. 해당 언어에 맞게 고칠 수 있어.
label         작업실 목록에 보이는 기획 이름.
imageBrief    제작자가 참고할 그림 메모. 실제 사진 설정은 바뀌지 않아.
slides        슬라이드 배열. 기존 장수·순서를 유지해.
caption       인스타그램 게시물 캡션.
hashtags      해시태그 문자열 배열. 최대 5개.

슬라이드마다 eyebrow, title, body, note 네 문자열 필드를 모두 유지해.
eyebrow는 작은 제목, title은 큰 제목, body는 본문, note는 짧은 덧말이야.
장수는 3장 또는 이전 형식의 5장이야. 이 기능으로 장수를 바꿀 수는 없어.

아래는 구조를 보여 주기 위한 예시이며 그대로 가져오는 파일이 아니야. 실제 데이터의 id와 baseRevision을 사용해야 해.

{
  "format": "sajupinggye-instagram-copy",
  "version": 1,
  "posts": [
    {
      "id": "example-only",
      "locale": "ko",
      "baseRevision": "0000000000000000",
      "topic": "짝사랑",
      "label": "답장 하나에 하루가 달라진다면",
      "imageBrief": "저녁 창가에 놓인 휴대폰. 오른쪽은 글을 넣을 넓은 여백.",
      "slides": [
        { "eyebrow": "도사의 연애 수첩", "title": "답장 하나에 왜 이렇게 흔들릴까?", "body": "답장이 늦으면 별생각이 다 들지.", "note": "짝사랑의 한 장면" },
        { "eyebrow": "사주를 일상에 빗대면", "title": "기다리는 동안, 네 할 일 하나", "body": "상대가 무슨 생각인지 답장 시간만으로 알 수는 없어. 오늘은 휴대폰을 내려놓고 끝낼 일 하나부터 골라 봐.", "note": "답장을 확인할 시간을 정해 봐" },
        { "eyebrow": "여기서 네 이야기로", "title": "사랑할 때의 나부터 보자", "body": "사주핑계에서 네 성향부터 살펴봐.", "note": "프로필 링크에서 이어보기" }
      ],
      "caption": "답장을 기다리는 동안 자꾸 휴대폰을 보게 된다면.\n\n프로필 링크에서 네 성향부터 살펴봐.",
      "hashtags": ["#사주핑계", "#짝사랑", "#연애성향"]
    }
  ]
}

4. 길이 제한

topic: 100자 / label: 160자 / imageBrief: 1,200자
eyebrow: 180자 / title: 180자 / body: 1,400자 / note: 360자
해시태그: 최대 5개, 각각 80자, 공백 없이 #으로 시작.
caption과 해시태그를 실제 게시용으로 합친 길이: 최대 2,200자.
작업실은 자바스크립트 문자열 길이로 검사하므로 일부 이모지는 2자로 계산될 수 있어.
최대 길이 이내여도 카드 화면에 빽빽할 수 있으니 최종 이미지에서 한 번 확인해.

5. 가져올 때 바뀌는 것

목록 이름, 현지 주제, 그림 메모, 각 장의 문구, 캡션, 해시태그만 바뀌어.
배경 사진, 직접 업로드한 이미지, 배경 위치, 디자인 템플릿, 게시 완료 표시는 유지돼.
미리보기에서 적용하기 전에는 저장된 글이 바뀌지 않아.
형식 오류·중복 ID와 언어·현재 원고와의 충돌이 있으면 선택한 파일을 한꺼번에 적용하지 않고 먼저 알려 줘.
기본으로 켜져 있는 ‘선택한 원고 전체 확인’에서는 현재 선택한 원고의 모든 ID·언어가 결과에 들어 있는지 확인해. 한국어만 들어 있는 결과처럼 일부가 빠졌다면 전체 교체로 적용할 수 없어. 내용이 원문과 같아도 검토 완료 여부를 자동으로 판단할 수는 없으니, 미리보기의 언어별 변경 개수를 확인하고 각 언어의 문장도 살펴봐.
특정 언어나 기획만 고치려는 경우에만 ‘선택한 원고 전체 확인’ 체크를 꺼. 이때 한국어 파일 하나를 올리면 해당 한국어 원고만 바뀌고 다른 언어는 유지돼. 일부 파일을 전체 수정 결과로 오해해서 적용하지 않도록 가져오기 설정을 확인해 줘.
JSON 대신 ZIP을 직접 올리지 말고, ZIP을 푼 뒤 수정한 JSON 파일을 골라.

6. 저장과 백업

가져온 문구는 지금 사용하는 브라우저의 작업실에 저장돼. GitHub의 기본 원고를 수정하거나 다른 컴퓨터와 자동으로 동기화하지 않아.
다른 브라우저나 컴퓨터로 옮길 때는 작업실의 전체 백업/복원 기능을 사용해. 사진까지 옮기려면 사진 포함 백업을 선택해.
GPT용 원고 파일은 문구 교환 전용이며 사진과 디자인을 보존하는 전체 백업을 대신하지 않아. 대량 수정 전에는 전체 백업을 하나 받아 둬.

적용 직후에는 ‘이번 교체 되돌리기’로 이전 문구를 다시 확인하고 적용할 수 있어. 이 버튼은 현재 탭에서 새로고침 전까지만 남아. 나중에도 되돌리고 싶다면 ‘되돌리기 JSON 받기’를 눌러 보관하고, 같은 가져오기 버튼으로 올려. 되돌리기 JSON은 바뀐 행만 담으므로, 파일로 다시 올릴 때는 ‘선택한 원고 전체 확인’을 꺼 줘. 적용한 문구를 그 뒤에 직접 수정했다면 해당 문구의 충돌을 먼저 확인해 줘. 되돌리기도 문구만 바꾸므로 사진과 게시 기록은 유지돼.
