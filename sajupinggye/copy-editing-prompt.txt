사주핑계 인스타그램 원고 편집 요청

첨부한 ZIP 안의 all-posts.json에 들어 있는 인스타그램 원고 전체를 사람이 직접 쓴 것처럼 자연스럽고 구체적인 글로 다듬어 줘. ZIP을 풀고 manifest.json에서 전체 개수와 언어별 개수를 확인한 뒤 all-posts.json 하나를 원본으로 작업해. 기본 키트는 한국어 ko 139개, 일본어 ja 139개, 영어 en 139개로 총 417개야. 한국어만 처리하지 말고 세 언어의 모든 행을 각각 해당 언어로 검토·수정해. 브라우저에서 새로 내보낸 ZIP은 개수가 다를 수 있으니 그때는 첨부한 manifest와 all-posts.json의 실제 개수를 기준으로 해.

설명이나 평가문 대신, 수정된 모든 행을 담은 UTF-8 첨부 파일 all-posts-edited.json 하나를 반환해. ZIP 안에는 원고 JSON이 all-posts.json 하나뿐이므로 언어 파일이나 배치 파일을 따로 찾을 필요가 없어. JSON 파일 하나만 첨부했다면 그 파일의 모든 행을 같은 규칙으로 처리하고 원래 파일명 끝에 -edited를 붙여 반환해.

작업을 시작할 때 원본의 전체 행 수, 언어별 행 수, (id, locale, baseRevision)의 순서 있는 목록과 각 행의 슬라이드 수를 별도로 기록해 둬. 반환 직전에 결과와 대조해 누락·추가·중복·식별자 변경이 없음을 확인해. 언어별 개수가 맞더라도 검토하지 않은 원문을 그대로 채워 넣고 수정 완료라고 하지 마. 모든 행을 읽고 필요한 문구를 다듬되, 이미 자연스러운 문장까지 억지로 바꿀 필요는 없어.

파일 생성이 불가능하거나 실행·출력 한도 때문에 전부 마칠 수 없다면 완료한 척하지 마. 어떤 언어의 몇 개가 끝났고 어떤 언어·ID가 남았는지 명시하고, 다음 응답에서 이어서 작업할 수 있도록 진행 상황을 남겨 줘. 이 경우에만 파일만 반환하라는 조건보다 미완료 사실을 알리는 것이 우선이야. 일부 결과나 검토하지 않은 원문으로 전체 완료 파일을 만들어 반환하지 말고, 남은 작업을 마친 뒤 모든 행을 담은 최종 파일을 생성해.

브랜드와 독자
- 사주핑계는 한국의 사주를 바탕으로 자신의 성향과 일상의 고민을 가볍게 돌아보는 서비스야.
- 짝사랑, 연락, 재회, 궁합, 시험, 자녀, 가족, 일, 돈, 이름처럼 구체적인 장면에서 시작해. 각 게시물의 원래 주제는 유지해.
- 제목은 한눈에 궁금증이 생기게 써. 내용은 제목에서 던진 질문을 실제로 받아 줘. 자극적인 제목 뒤에 아무 글이나 붙이지 마.
- 3장 원고는 ① 공감할 장면과 질문 ② 사주 개념으로 짚어 보는 이유와 현실적인 제안 ③ 사주핑계에서 자신의 성향을 보도록 연결하는 순서야. 이전 형식의 5장 원고는 기존 장수와 흐름을 유지하며 다듬어.

말투
- locale=ko: 친근한 도사가 옆에서 이야기해 주는 반말. “한번 봐”, “그럴 때 있지”, “이렇게 해 봐”처럼 자연스럽게 써. “자네”, “그대”, “하거라”, “허허” 같은 연극 말투와 훈계는 피해야 해.
- locale=ja: 일본 독자가 평소 읽는 연애·생활 매거진처럼 자연스러운 일본어. 한국어 문장 구조를 옮기지 말고, 친근하되 지나치게 유아적이거나 단정적인 말투는 피해야 해. 四柱推命・サジュ라는 맥락을 필요할 때 짧게 설명해.
- locale=en: 영어권의 관계·라이프스타일 콘텐츠처럼 구체적이고 편한 영어. 한국어의 추상어와 완곡한 문장 구조를 직역하지 마. Saju가 낯선 독자를 고려해 필요한 게시물에서는 Korean birth-chart tradition처럼 짧게 소개해. 서양 점성술이나 별자리와 같은 것으로 설명하지 마.
- 브랜드 표기는 한국어 사주핑계, 일본어 サジュピンゲ, 영어 SajuPinggye를 사용해.
- 지역별 시험 제도·관계 표현·생활 장면을 존중해. 같은 ID라도 언어별 주제가 다를 수 있으니 각 행의 topic과 원문을 기준으로 작업해. 한국의 수능을 일본·미국 콘텐츠에 그대로 옮기지 마.

가장 중요한 문장 검수 기준
1. 먼저 각 문장을 소리 내어 읽는다고 생각해. 실제 사람이 그 상황에서 할 법한 말인지 확인해.
2. 주어와 행동, 원인과 결과가 이어져야 해. “분위기를 지키는 일이 커진다”처럼 행동이 떠오르지 않는 문장은 구체적인 상황으로 다시 써.
3. “기운”, “흐름”, “균형”, “가능성”, “리듬” 같은 말로 설명을 대신하지 마. 어떤 순간에 누가 무엇을 하는지 보여 줘.
4. 쉼표를 습관적으로 넣지 마. 한국어에서 “오늘은, 네 마음을, 먼저 살펴봐”처럼 호흡을 인위적으로 나누지 마. 자연스러운 쉼표는 남겨도 돼.
5. “단순히 A가 아니라 B”, “중요한 건”, “기억해”, “괜찮아” 같은 틀을 여러 게시물에서 반복하지 마. 무조건 위로로 끝내지 말고 그 주제에 맞는 관찰이나 작은 행동으로 마무리해.
6. 앞 문장을 말만 바꿔 다시 쓰거나, 비유를 설명하느라 더 추상적으로 만드는 문장은 삭제하거나 다시 써. 다만 장수와 필드 자체를 지우면 안 돼.
7. 제목·본문·캡션이 같은 말을 기계적으로 반복하지 않게 해. 캡션은 게시물의 맥락을 보충하되 카드 내용을 빠짐없이 길게 복제할 필요는 없어.
8. 명리 용어는 생활 장면을 설명하는 비유와 관점으로 사용해. 모든 독자에게 개인 명식을 계산한 것처럼 말하지 마. 기술적 설명을 고칠 때는 뜻을 모르는 용어를 창작하지 마.
9. 시험 합격, 연락·재회 날짜, 상대의 속마음, 투자 수익, 건강, 작명 효과를 확정하거나 보장하지 마. 불안을 키워 설치·구매를 재촉하는 표현도 피해야 해.
10. 현재 제공 여부를 확인할 수 없는 기능·가격·할인·상담·스토어 출시 상태를 새로 약속하지 마. 귀인 지도, 상대방 속마음 확인, 합격 예측 등을 임의로 CTA에 넣지 마. “프로필 링크에서 네 성향부터 살펴봐”처럼 확인 가능한 범위로 연결해.

길이와 편집 방향
- 첫 장의 제목은 짧고 직관적으로 써. 제목만 봐도 연애인지 시험인지 어떤 장면인지 알 수 있어야 해.
- 제목의 권장 길이는 한국어 10~26자, 일본어 12~30자, 영어 4~10단어 정도야. 꼭 맞추려고 문장을 망가뜨리지는 마.
- 두 번째 장은 설명 하나와 구체적인 제안 하나 정도면 충분해. 긴 사주 이론 강의로 만들지 마.
- 마지막 장은 다른 게시물에서도 돌려 쓸 수 있는 짧은 앱·서비스 연결 문구로 써. 설치 가능 여부를 단정하지 말고 프로필 링크로 안내해.
- imageBrief는 제작자용 그림 메모라 한국어로 남겨도 돼. 장면을 보완할 수 있지만 사진 URL, 인물 이름, 파일 경로, 저작권이 확보됐다는 문구를 만들지 마.
- 해시태그는 해당 언어의 실제 독자가 쓸 법한 것만 최대 5개. 각 항목은 #으로 시작하고 공백을 넣지 마. 캡션과 해시태그를 이어 붙인 전체 길이는 2,200자 이내로 맞춰.

반드시 지킬 JSON 규격
- 최상위는 format, version, posts 세 필드만 유지해.
- format은 "sajupinggye-instagram-copy", version은 숫자 1이야.
- posts 배열의 행 개수와 순서를 그대로 유지해. 누락·추가·중복 없이 첨부 파일의 모든 행을 수정해.
- 각 행의 id, locale, baseRevision은 글자 하나도 바꾸지 마. baseRevision은 가져오기 충돌을 확인하는 값이므로 다시 계산하거나 새로 만들면 안 돼.
- 각 행에는 id, locale, baseRevision, topic, label, imageBrief, slides, caption, hashtags를 모두 넣어.
- 수정 가능한 것은 topic, label, imageBrief, slides 안의 eyebrow/title/body/note, caption, hashtags뿐이야.
- slides 배열의 장수와 순서를 유지해. 슬라이드마다 eyebrow, title, body, note 네 문자열 필드를 모두 넣어. 원래 빈 문자열인 필드도 생략하지 마.
- topic과 label은 빈 문자열로 만들지 마. 줄바꿈은 문자열 안의 \n으로 표현해.
- hashtags는 문자열 배열로 유지해. 문자열 하나에 모든 태그를 합치면 안 돼.
- 허용하지 않는 새 필드, JSON 주석, 마크다운 코드 블록, 말줄임표로 대체한 원고, 요약문을 넣지 마.
- 따옴표는 JSON 문법에 맞게 이스케이프해. HTML이나 스크립트를 넣지 마.
- 아래 숫자는 파일 검증의 최대 길이야. 이 길이를 채우라는 뜻은 아니야: topic 100자, label 160자, imageBrief 1,200자, eyebrow 180자, title 180자, body 1,400자, note 360자. 해시태그 하나는 80자 이내.

반환 직전 확인
JSON이 파싱되는지 확인하고 다음 항목을 원본과 실제로 대조해.
- 전체 posts 수와 ko / ja / en 각각의 행 수가 같아야 해. 기본 키트라면 417개, ko 139개, ja 139개, en 139개야.
- 모든 (id, locale) 집합이 정확히 같고 중복이 없어야 해. 각 행의 baseRevision과 순서, 슬라이드 장수도 그대로여야 해.
- 한국어·일본어·영어의 모든 행을 해당 언어의 말투와 문장 검수 기준으로 검토했는지 확인해. 한국어만 수정하고 다른 언어를 원문으로 채워 넣지 마.
- 위 기준으로 어색한 문장과 과장된 주장을 한 번 더 고쳐.

전체 작업이 끝났다면 설명은 첨부 파일 밖에도 덧붙이지 말고 all-posts-edited.json 파일 하나만 반환해 줘. ZIP 대신 JSON 하나만 입력했다면 원래 파일명 끝에 -edited를 붙여 줘. 완료하지 못했다면 앞서 정한 미완료 안내 규칙을 따라.
